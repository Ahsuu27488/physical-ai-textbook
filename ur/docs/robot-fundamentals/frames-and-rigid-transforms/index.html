Frames and rigid transforms

Intermediate40 minBefore this:Python and NumPy basics · Matrix multiplication · Trigonometry

A camera on a robot's head sees a red cup 0.6 m ahead and 0.1 m to the left. The arm needs to grasp it, but the arm does not speak "camera". It speaks "shoulder". Somebody has to convert between the two, and if the conversion is wrong by a few degrees the gripper closes on thin air. This lesson is about that conversion: the single most used tool in all of robotics.

If matrices still feel rusty, skim Linear algebra and transforms first. This lesson goes further and builds code you will reuse for the rest of the course.

You will be able to

  • Describe a pose (position plus orientation) of one coordinate frame relative to another.
  • Build and apply rotation matrices and 4×4 homogeneous transforms in NumPy.
  • Compose and invert transforms, and read the order of multiplication correctly.
  • Explain why Euler angles can fail (gimbal lock) and convert between rotation matrices and quaternions.
  • Use frame notation such as ATB{}^{A}T_{B}ATB​ without getting lost.

Frames: a place to stand​

A framea coordinate system, with an origin point and three perpendicular axes, attached to a place or an object is a set of axes you measure from. The world has one. So does the robot's base, each link of its arm, and each sensor. A point has no meaning until you say which frame its coordinates are in: "(1, 0, 0)" in the base frame is a different spot from "(1, 0, 0)" in the camera frame.

We write Ap{}^{A}pAp for "the point ppp, expressed in frame AAA", and ATB{}^{A}T_{B}ATB​ for "the pose of frame BBB expressed in frame AAA". Read the superscript as "in" and the subscript as "of": the transform of BBB, seen from AAA. This notation is worth the effort because errors become visible. If you multiply a point in BBB by ATB{}^{A}T_{B}ATB​, the matching letters cancel and you get a point in AAA:

Ap=ATB  Bp{}^{A}p = {}^{A}T_{B}\;{}^{B}pAp=ATB​Bp

Letters should cancel

When you chain transforms, write the frame letters and check that the inner ones match and cancel, like ATB BTC=ATC{}^{A}T_{B}\,{}^{B}T_{C} = {}^{A}T_{C}ATB​BTC​=ATC​. If they do not cancel, your code is wrong before you run it.

Rotations​

In 2D, rotating a point by angle θ\thetaθ is familiar. In 3D we use a 3×33 \times 33×3 rotation matrixa square matrix R with R transposed times R equal to identity and determinant +1; it rotates vectors without stretching them. The three basic rotations, about the xxx, yyy and zzz axes, are:

Rz(θ)=[cos⁡θ−sin⁡θ0sin⁡θcos⁡θ0001]R_z(\theta) = \begin{bmatrix} \cos\theta & -\sin\theta & 0 \\ \sin\theta & \cos\theta & 0 \\ 0 & 0 & 1 \end{bmatrix}Rz​(θ)=​cosθsinθ0​−sinθcosθ0​001​​

and similarly for RxR_xRx​ and RyR_yRy​. Two properties make rotations pleasant:

  • The inverse is the transpose: R−1=RTR^{-1} = R^{\mathsf T}R−1=RT. No matrix inversion needed.
  • Order matters: rotating 90° about xxx then 90° about zzz is a different orientation from zzz then xxx. Try it with a book.

Each column of RRR is where one axis of the rotated frame points, written in the parent frame. That gives a quick sanity check: the columns must be perpendicular unit vectors.

Homogeneous transforms: rotation and translation in one matrix​

A pose has an orientation RRR and a position ppp. Applying it to a point xxx is Rx+pRx + pRx+p. That is not a pure matrix product, which is annoying. The trick is to add a fourth coordinate equal to 1 and pack both parts into a 4×44 \times 44×4 homogeneous transforma 4x4 matrix that combines a rotation and a translation so a rigid motion becomes a single matrix multiplication:

T=[Rp0  0  01],[x′1]=T[x1]T = \begin{bmatrix} R & p \\ 0\;0\;0 & 1 \end{bmatrix}, \qquad \begin{bmatrix} x' \\ 1 \end{bmatrix} = T \begin{bmatrix} x \\ 1 \end{bmatrix}T=[R000​p1​],[x′1​]=T[x1​]

Now a rigid motion is one multiplication, and composition is just matrix multiplication. The inverse has a neat closed form that avoids a general matrix inverse:

T−1=[RT−RTp0  0  01]T^{-1} = \begin{bmatrix} R^{\mathsf T} & -R^{\mathsf T} p \\ 0\;0\;0 & 1 \end{bmatrix}T−1=[RT000​−RTp1​]

Here is a small library. We will reuse it in the next lessons.

transforms.py
import numpy as np


def rot_x(a):
    c, s = np.cos(a), np.sin(a)
    return np.array([[1, 0, 0], [0, c, -s], [0, s, c]])


def rot_y(a):
    c, s = np.cos(a), np.sin(a)
    return np.array([[c, 0, s], [0, 1, 0], [-s, 0, c]])


def rot_z(a):
    c, s = np.cos(a), np.sin(a)
    return np.array([[c, -s, 0], [s, c, 0], [0, 0, 1]])


def make_T(R, p):
    """Pack a 3x3 rotation and a 3-vector into a 4x4 homogeneous transform."""
    T = np.eye(4)
    T[:3, :3] = R
    T[:3, 3] = p
    return T


def invert_T(T):
    """Closed-form inverse of a rigid transform (cheaper and more accurate than np.linalg.inv)."""
    R, p = T[:3, :3], T[:3, 3]
    Ti = np.eye(4)
    Ti[:3, :3] = R.T
    Ti[:3, 3] = -R.T @ p
    return Ti


def apply_T(T, point):
    """Transform a 3D point (length-3 array) by a 4x4 transform."""
    return (T @ np.append(point, 1.0))[:3]


if __name__ == "__main__":
    # Camera sits 0.5 m above and 0.1 m forward of the robot base, tilted down 30 degrees.
    base_T_cam = make_T(rot_y(np.deg2rad(30)), [0.1, 0.0, 0.5])
    cup_in_cam = np.array([0.6, 0.1, 0.0])           # cup as the camera sees it
    cup_in_base = apply_T(base_T_cam, cup_in_cam)    # same cup, in the base frame
    print("cup in base frame:", np.round(cup_in_base, 3))

    # Going back: the inverse transform undoes it.
    back = apply_T(invert_T(base_T_cam), cup_in_base)
    print("round trip ok:", np.allclose(back, cup_in_cam))
    print("R is a rotation:", np.allclose(base_T_cam[:3, :3].T @ base_T_cam[:3, :3], np.eye(3)))

Composition and the order of multiplication​

Suppose the world-to-base pose is WTB{}^{W}T_{B}WTB​ and the base-to-camera pose is BTC{}^{B}T_{C}BTC​. The camera's pose in the world is

WTC=WTB  BTC{}^{W}T_{C} = {}^{W}T_{B}\;{}^{B}T_{C}WTC​=WTB​BTC​

The letters cancel, so the order is right. Reading left to right, you move down the chain of frames from the world to the camera. A common bug is multiplying in the opposite order; the result is still a valid transform, just for a different robot than the one you built.

There are two equivalent mental models, and being able to switch between them is a superpower:

  • Intrinsic (body-fixed) view: each new rotation is about the current, already-moved axes. Multiply new transforms on the right.
  • Extrinsic (fixed-frame) view: each new rotation is about the original, fixed axes. Multiply new transforms on the left.
compose.py
import numpy as np
from transforms import rot_z, make_T, invert_T, apply_T

# A robot standing at (2, 1) in the world, facing +y (yaw 90 degrees).
world_T_base = make_T(rot_z(np.pi / 2), [2.0, 1.0, 0.0])
# A lidar 0.3 m in front of the base centre, same orientation.
base_T_lidar = make_T(np.eye(3), [0.3, 0.0, 0.2])

world_T_lidar = world_T_base @ base_T_lidar           # letters cancel: W.B then B.L
print("lidar position in the world:", world_T_lidar[:3, 3])

# A wall point seen 4 m straight ahead of the lidar:
hit_in_lidar = np.array([4.0, 0.0, 0.0])
print("hit in the world:", apply_T(world_T_lidar, hit_in_lidar))

# What is the base pose seen from the lidar? Invert and compose.
lidar_T_base = invert_T(base_T_lidar)
print(np.allclose(base_T_lidar @ lidar_T_base, np.eye(4)))

Check the first print by hand: the base faces +y+y+y, so "0.3 m forward" moves the lidar to (2,1.3)(2, 1.3)(2,1.3) in the world. If you get (2.3,1)(2.3, 1)(2.3,1) you have the order or the rotation wrong.

Euler angles, and why they bite​

The most intuitive way to describe an orientation is three angles: roll, pitch, yaw. These are Euler anglesthree successive rotations about chosen axes that together describe any 3D orientation. Humans like them; they are easy to read and plot. But they have two problems.

  1. Convention chaos. "Roll, pitch, yaw" can mean rotating about xxx, yyy, zzz in different orders, in fixed or moving axes. Two libraries can disagree about the same three numbers. ROS uses fixed-axis roll-pitch-yaw (about xxx, then yyy, then zzz of the fixed frame), which equals the matrix Rz(yaw) Ry(pitch) Rx(roll)R_z(\text{yaw})\,R_y(\text{pitch})\,R_x(\text{roll})Rz​(yaw)Ry​(pitch)Rx​(roll).
  2. Gimbal lock. At a pitch of 90°, two axes line up and you lose a degree of freedom. Different yaw/roll combinations give the same orientation, and the angles jump wildly near that point.

Prove the lock to yourself:

gimbal.py
import numpy as np
from transforms import rot_x, rot_y, rot_z

pitch = np.pi / 2
A = rot_z(0.8) @ rot_y(pitch) @ rot_x(0.5)
B = rot_z(0.3) @ rot_y(pitch) @ rot_x(0.0)
print("different angles, same orientation:", np.allclose(A, B))

Only the difference "yaw minus roll" matters at the lock. One degree of freedom has vanished.

Quaternions: four numbers that behave​

A unit quaterniona four-number representation of a 3D rotation, usually written (w, x, y, z), with unit length represents a rotation by an axis n^\hat{n}n^ and an angle θ\thetaθ:

q=(cos⁡θ2,  n^sin⁡θ2)=(w,x,y,z),w2+x2+y2+z2=1q = \left(\cos\tfrac{\theta}{2},\; \hat{n}\sin\tfrac{\theta}{2}\right) = (w, x, y, z), \qquad w^2 + x^2 + y^2 + z^2 = 1q=(cos2θ​,n^sin2θ​)=(w,x,y,z),w2+x2+y2+z2=1

Advantages over Euler angles: no gimbal lock, smooth interpolation (slerp, spherical linear interpolation), and compact, cheap composition. Two quirks to remember: qqq and −q-q−q describe the same rotation, and ROS stores them in the order (x,y,z,w)(x, y, z, w)(x,y,z,w) while many math texts write (w,x,y,z)(w, x, y, z)(w,x,y,z). Always check the order.

quaternions.py
import numpy as np


def quat_to_R(q):
    w, x, y, z = q / np.linalg.norm(q)
    return np.array([
        [1 - 2*(y*y + z*z), 2*(x*y - z*w),     2*(x*z + y*w)],
        [2*(x*y + z*w),     1 - 2*(x*x + z*z), 2*(y*z - x*w)],
        [2*(x*z - y*w),     2*(y*z + x*w),     1 - 2*(x*x + y*y)],
    ])


def R_to_quat(R):
    tr = np.trace(R)
    if tr > 0:
        s = 2.0 * np.sqrt(tr + 1.0)
        w = 0.25 * s
        x = (R[2, 1] - R[1, 2]) / s
        y = (R[0, 2] - R[2, 0]) / s
        z = (R[1, 0] - R[0, 1]) / s
    else:
        i = int(np.argmax(np.diag(R)))
        j, k = (i + 1) % 3, (i + 2) % 3
        s = 2.0 * np.sqrt(1.0 + R[i, i] - R[j, j] - R[k, k])
        q = np.zeros(4)
        q[1 + i] = 0.25 * s
        q[0] = (R[k, j] - R[j, k]) / s
        q[1 + j] = (R[j, i] + R[i, j]) / s
        q[1 + k] = (R[k, i] + R[i, k]) / s
        w, x, y, z = q
    q = np.array([w, x, y, z])
    return q if q[0] >= 0 else -q          # pick the sign with w >= 0


def quat_mul(a, b):
    aw, ax, ay, az = a
    bw, bx, by, bz = b
    return np.array([
        aw*bw - ax*bx - ay*by - az*bz,
        aw*bx + ax*bw + ay*bz - az*by,
        aw*by - ax*bz + ay*bw + az*bx,
        aw*bz + ax*by - ay*bx + az*bw,
    ])


def slerp(q0, q1, t):
    d = float(np.dot(q0, q1))
    if d < 0.0:                            # take the short way round
        q1, d = -q1, -d
    if d > 0.9995:                         # nearly equal: plain lerp is fine
        q = q0 + t * (q1 - q0)
        return q / np.linalg.norm(q)
    theta = np.arccos(d)
    return (np.sin((1 - t) * theta) * q0 + np.sin(t * theta) * q1) / np.sin(theta)


if __name__ == "__main__":
    from transforms import rot_x, rot_z
    R = rot_z(0.7) @ rot_x(1.1)
    q = R_to_quat(R)
    print("round trip:", np.allclose(quat_to_R(q), R))
    qa, qb = R_to_quat(rot_z(0.5)), R_to_quat(rot_x(0.4))
    print("composition matches:", np.allclose(quat_to_R(quat_mul(qa, qb)), rot_z(0.5) @ rot_x(0.4)))
    print("halfway to 90 degrees about z:", np.round(slerp(R_to_quat(np.eye(3)), R_to_quat(rot_z(np.pi / 2)), 0.5), 4))

In practice you will rarely write these by hand; libraries such as scipy.spatial.transform.Rotation and the ROS tf_transformations helpers do it for you. Writing it once is what lets you trust them.

Pro tip

Store and pass orientations as quaternions or rotation matrices. Use Euler angles only at the edges: to display a value to a human or to read a human-typed angle.

Hands-on lab​

You will build a two-frame setup and verify it numerically.

  1. Save transforms.py and quaternions.py from this lesson in one folder.
  2. Create a world frame, a robot base at (1,2,0)(1, 2, 0)(1,2,0) with yaw 45°, and a camera on the base at (0.2,0,0.6)(0.2, 0, 0.6)(0.2,0,0.6) pitched down 20° (use rot_y(np.deg2rad(20))).
  3. Compute world_T_cam by multiplying the two transforms. Print the camera position.
  4. A detection arrives: a mug at (1.5,0,0)(1.5, 0, 0)(1.5,0,0) in the camera frame. Convert it to the world frame with apply_T.
  5. Convert it back with invert_T and check you recover (1.5,0,0)(1.5, 0, 0)(1.5,0,0) with np.allclose.
  6. Convert world_T_cam[:3, :3] to a quaternion and back, and confirm the matrix is unchanged.

You know it worked when every round trip passes np.allclose and the camera sits above and slightly ahead of the base position, rotated 45° about the vertical axis.

Is it still a rotation?Intermediate

After many floating-point multiplications a rotation matrix can drift. Write a function that re-orthonormalizes a drifted 3×3 matrix using the SVD.

Show solutionHide solution
import numpy as np

def nearest_rotation(M):
    U, _, Vt = np.linalg.svd(M)
    R = U @ Vt
    if np.linalg.det(R) < 0:      # fix a reflection
        U[:, -1] *= -1
        R = U @ Vt
    return R

The SVD finds the closest orthogonal matrix to M; the determinant check flips the sign if the result is a mirror image rather than a true rotation.

Takeaways

  • Every coordinate needs a frame; write ATB{}^{A}T_{B}ATB​ and make the letters cancel when you chain transforms.
  • A rotation matrix is orthonormal with an inverse equal to its transpose; order of rotations matters.
  • A 4×4 homogeneous transform packs rotation and translation so composition becomes matrix multiplication.
  • Invert rigid transforms in closed form: transpose the rotation and rotate the negated translation.
  • Euler angles are readable but suffer from gimbal lock and convention confusion.
  • Quaternions avoid gimbal lock and interpolate smoothly; watch for the (x, y, z, w) versus (w, x, y, z) ordering.
